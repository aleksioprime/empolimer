# Протоколы обмена

```text
                 USB (Serial 115200)                MQTT                       HTTP / WebSocket
 Raspberry  ◄──────────────────────►  ESP  ──────────────────►  worker → PostgreSQL → backend  ◄────  браузер
 (камера,         JSON + команды            empolimer/<id>/…                                (веб-мониторинг)
  дисплей)                                    ▲
                                              └── SD-карта: config.json, журнал, очередь
```

## ESP ↔ Raspberry (USB)

Скорость **115200**, одна строка — одно сообщение, окончание `\n`.

### ESP → Raspberry

| Строка | Когда |
| --- | --- |
| `{"type":"data","ts":1760000000,"temp":23.5,"hum":41.0}` | каждое измерение; `ts` нет, пока часы ESP не установлены; `bat` — если включено измерение батареи |
| `{"type":"status", ...}` | при старте, раз в минуту, при изменениях и по команде `STATUS` (поля — ниже) |
| `{"type":"ack","cmd":"LIGHT ON","ok":true}` | ответ на команду; при ошибке `"ok":false,"error":"..."` |
| `# текст` | журнал для человека — программа его не разбирает |

Строки, которые не начинаются с `{` или `#` (например, вывод загрузчика
ESP8266 при сбросе), нужно пропускать.

### Raspberry → ESP

| Команда | Действие |
| --- | --- |
| `STATUS` | прислать состояние |
| `READ` | измерить сейчас |
| `LIGHT ON` / `LIGHT ON 120` | включить подсветку (яркость 0–255) |
| `LIGHT OFF` | выключить |
| `LIGHT AUTO` | вернуть расписание из `config.json` |
| `TIME 1760000000` | установить часы (unix-время, секунды) |
| `HELP` | список команд в журнал |

Регистр не важен. Станция на Raspberry отправляет `TIME` при подключении и раз
в час, если её собственные часы синхронизированы по интернету.

## ESP → сервер (MQTT)

`prefix` — `mqtt.prefix` в `config.json` (по умолчанию `empolimer`),
`id` — `device.id`.

| Топик | QoS / retain | Содержимое |
| --- | --- | --- |
| `<prefix>/<id>/data` | 0 | `{"ts":1760000000,"temp":23.5,"hum":41.0,"bat":3.91}` — `ts` и `bat` необязательны |
| `<prefix>/<id>/status` | retain | состояние (ниже); при обрыве брокер публикует `{"online":false}` (Last Will) |
| `<prefix>/<id>/cmd` | — | команды устройству, те же, что по USB |

Измерения, которые не удалось отправить, ESP складывает в очередь на SD и
досылает после восстановления связи с исходным `ts`. Сервер хранит одно
измерение на пару (устройство, время), поэтому повторы безопасны.

Сервер также принимает старый формат: топик `devices/<id>/air`, поле
`datetime` (ISO-строка) вместо `ts`.

### Поля состояния

| Поле | Значение |
| --- | --- |
| `online` | `true` от устройства, `false` — Last Will от брокера |
| `id`, `fw`, `board` | идентификатор, версия прошивки, `esp8266` / `esp32` |
| `uptime`, `interval` | секунд с запуска, период измерений |
| `wifi`, `ip`, `rssi` | подключение, адрес, уровень сигнала (дБм) |
| `mqtt` | подключение к брокеру |
| `time` | часы установлены |
| `sd`, `config_error` | SD-карта найдена; ошибка чтения `config.json` |
| `sensor` | датчик отвечает |
| `queue` | сколько измерений ждут отправки |
| `light`, `light_auto`, `brightness` | подсветка включена, работает по расписанию, яркость |

## Сервер → браузер

REST API — `/api/openapi` (Swagger). Живое обновление —
`/api/v1/devices/ws/?token=<access-token>`: сервер присылает
`{"type":"devices_update","devices":[...]}` при изменениях и не реже раза в
30 секунд; на `ping` отвечает `pong`.
